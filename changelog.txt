= Changelog =

== 1.2.0 – 2026-05-14 ==
* Added: Self-update from GitHub releases. The plugin polls api.github.com/repos/znackarna/wordpress-update-logger/releases/latest once per 12 h and injects the latest tag into the WordPress update transient, so new versions appear in the standard "Plugins → Updates available" UI without any external library
* Added: register_update_checker() wires three filters (pre_set_site_transient_update_plugins, plugins_api, upgrader_source_selection) and a 12-hour cached fetch_latest_release() helper. The upgrader_source_selection hook renames GitHub's zipball folder (znackarna-wordpress-update-logger-&lt;sha&gt;) to the canonical wordpress-update-logger slug so the plugin path survives the update
* Note: Updates are driven by GitHub releases — without a published release (gh release create vX.Y.Z) no site sees the update. Header version must match the release tag (Version: X.Y.Z in plugin header, tag vX.Y.Z on GitHub)

== 1.1.9 – 2026-04-30 ==
* Removed: Diagnostic ring buffer (HOOK_LOG_KEY site option, record_hook_fire helper, admin notice block, ul_clear_hook_log handler). The redundant upgrader_overwrote_package hook from 1.1.8 verifiably catches ZIP-upload reinstalls in production, so the temporary debug surface is no longer needed
* Improved: on_manual_update install branch derives the plugin/theme from $upgrader->result['destination_name'] via a new resolver against the canonical full get_plugins() / wp_get_themes() catalog, falling back to $upgrader->plugin_info() / theme_info() only on miss. Avoids the cache/timing artifact where plugin_info() returned empty inside the upgrader_process_complete callback and the row had to rely entirely on the redundant hook
* Note: The 1.1.8 site option update_logger_hook_log is now orphaned. It is a tiny ring buffer (<2 KB) and will be left untouched; admins can delete it manually via the network options table if they care

== 1.1.8 – 2026-04-30 ==
* Added: Hook into upgrader_overwrote_package as a canonical fallback for ZIP-upload reinstalls (fires from Plugin_Upgrader::install() / Theme_Upgrader::install() after a successful overwrite). Plugin/theme is resolved by matching new metadata against the installed catalog
* Added: Per-request deduplication in insert_row to prevent duplicate rows when both upgrader_process_complete and upgrader_overwrote_package fire for the same overwrite
* Added: Temporary diagnostic ring buffer (last 10 upgrader hook fires, displayed as a notice on the admin log page with a Clear action). Captured before any guard so the admin can confirm whether the hook reaches the plugin at all. To be removed once the upload-overwrite logging path is verified across the affected hosting setups

== 1.1.7 – 2026-04-30 ==
* Fixed: ZIP-upload reinstalls (Plugins → Add New → Upload Plugin → Replace current with uploaded) are now logged. The previous overwrite check relied on a $hook_extra['overwrite'] key that WordPress never sets; the upgrader's clear_destination flag is checked instead, and the affected plugin/theme is derived from $upgrader->plugin_info() / theme_info() since action=install does not populate plugins/themes in $hook_extra
* Improved: Plugin/theme slug for upload-overwrite installs is resolved via the upgrader, so old/new versions are recorded the same way as for regular updates

== 1.1.6 – 2026-04-30 ==
* Improved: Pagination on the admin log page now uses the standard WordPress admin layout (item count, first/prev/next/last button controls) instead of plain numbered links
* Added: Translatable strings for pagination controls (item count, page X of Y, first/previous/next/last page)
